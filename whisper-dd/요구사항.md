이 시스템은 참가자별 디바이스에서 오디오를 로컬 캡처하고, 온디바이스 VAD와 ASR을 수행한 뒤, 회의 허브에서 시간순으로 합치는 **로컬 우선 회의 전사 시스템**이다. [github](https://github.com/SYSTRAN/faster-whisper)

## 1. 개요
- **시스템명**: 로컬 회의 전사 시스템.
- **목적**: 온라인 회의에서 참가자별 디바이스의 음성을 온디바이스로 전사하고, 결과를 병합해 회의록을 생성한다.
- **운영 원칙**: 오디오 원본은 가능하면 외부 서버로 보내지 않고, 전사 결과만 동기화한다.
- **대상 환경**: 온라인 회의, 각 참가자 1디바이스, 실시간 또는 준실시간 전사. [github](https://github.com/paberr/ownscribe)

## 2. 기능 요구사항
- **FR-01 오디오 캡처**: 각 디바이스는 마이크 입력을 실시간으로 수집해야 한다.
- **FR-02 포맷 통일**: 입력 오디오는 16kHz, mono, PCM 형식으로 정규화해야 한다. [github](https://github.com/snakers4/silero-vad)
- **FR-03 음성 구간 검출**: VAD를 사용해 발화 구간과 무음 구간을 분리해야 한다. [github](https://github.com/stefanwebb/open-voice-activity-detection)
- **FR-04 구간 전사**: 검출된 음성 구간을 온디바이스 ASR 엔진으로 텍스트로 변환해야 한다. [github](https://github.com/m-bain/whisperX)
- **FR-05 타임스탬프 부여**: 각 전사 결과에 시작/종료 시간을 포함해야 한다. [developers.openai](https://developers.openai.com/api/docs/guides/speech-to-text)
- **FR-06 참가자 식별**: 각 결과는 `participant_id` 또는 `device_id`와 연결되어야 한다.
- **FR-07 세션 병합**: 허브는 참가자별 전사 결과를 시간순으로 정렬해 하나의 회의록으로 합쳐야 한다.
- **FR-08 결과 저장**: 전사 결과는 JSON, TXT, SRT, VTT 중 하나 이상으로 내보낼 수 있어야 한다.
- **FR-09 실시간 표시**: 선택적으로 실시간 자막 뷰를 제공해야 한다.
- **FR-10 재처리**: 저장된 오디오 또는 세그먼트에 대해 재전사할 수 있어야 한다.

## 3. 비기능 요구사항
- **NFR-01 온디바이스 동작**: 핵심 전처리와 전사는 로컬 장치에서 수행되어야 한다. [meetily](https://meetily.ai/blog/best-privacy-focused-meeting-transcription-tools-2025/)
- **NFR-02 지연시간**: 실시간 모드에서 사용자 체감 지연은 수 초 이내여야 한다.
- **NFR-03 경량성**: 저사양 장치에서도 동작하도록 경량 모델 또는 양자화 모델을 고려해야 한다. [anarlog](https://anarlog.so/blog/local-ai-meeting-notes)
- **NFR-04 안정성**: 네트워크가 불안정해도 로컬 전사는 계속되어야 한다.
- **NFR-05 확장성**: 참가자 수가 늘어나도 세션 병합 구조가 유지되어야 한다.
- **NFR-06 보안/프라이버시**: 원본 음성은 로컬 저장 또는 암호화 전송을 기본으로 한다. [picovoice](https://picovoice.ai/use-cases/meeting-transcription/)
- **NFR-07 이식성**: 데스크톱, 노트북, 모바일 환경으로 확장 가능해야 한다. [github](https://github.com/SYSTRAN/faster-whisper)

## 4. 모듈 구성
- **M-01 Audio Capture**: 마이크 입력 수집.
- **M-02 Audio Normalizer**: 샘플레이트, 채널, 포맷 통일.
- **M-03 VAD Engine**: 발화 구간 추출.
- **M-04 ASR Engine**: Whisper 계열 전사.
- **M-05 Alignment Engine**: 단어/문장 타임스탬프 정렬.
- **M-06 Session Merger**: 참가자별 결과 병합.
- **M-07 Storage/Export**: JSON, SRT, VTT, TXT 저장.
- **M-08 UI/Viewer**: 실시간 자막, 회의록 확인 화면.

## 5. 인터페이스 요구사항
- **I-01 입력 인터페이스**: PCM 오디오 스트림.
- **I-02 내부 데이터 구조**: `participant_id`, `start_time`, `end_time`, `text`, `confidence`.
- **I-03 전송 인터페이스**: 로컬 허브로 JSON 이벤트 전송.
- **I-04 출력 인터페이스**: 병합된 transcript 파일과 실시간 UI 이벤트.
- **I-05 실패 인터페이스**: 전사 실패, VAD 실패, 동기화 실패를 구분한 에러 코드.

## 6. 데이터 형식 예시
```json
{
  "session_id": "meet-20260523-001",
  "participant_id": "p03",
  "start_time": 12.45,
  "end_time": 16.82,
  "text": "오늘 일정은 이렇게 정리하겠습니다.",
  "confidence": 0.93
}
```

## 7. 처리 흐름
1. 디바이스가 마이크 입력을 받는다.
2. 오디오를 16kHz mono PCM으로 맞춘다. [github](https://github.com/snakers4/silero-vad)
3. VAD가 말하는 구간만 분리한다. [github](https://github.com/stefanwebb/open-voice-activity-detection)
4. ASR이 해당 구간을 전사한다. [github](https://github.com/m-bain/whisperX)
5. 정렬 엔진이 타임스탬프를 보정한다. [developers.openai](https://developers.openai.com/api/docs/guides/speech-to-text)
6. 허브가 모든 디바이스 결과를 시간순으로 합친다.
7. 최종 회의록을 저장하거나 화면에 표시한다.

## 8. 구현 범위
- **필수 범위**: 오디오 캡처, VAD, ASR, 타임스탬프, 병합, 저장.
- **선택 범위**: 자막 뷰, 검색, 요약, 액션 아이템 추출.
- **제외 범위**: 화자 diarization, 보이스 인증, 클라우드 의존 전사.
